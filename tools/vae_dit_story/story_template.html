Wan2.2 VAE + DiT:从像素到生成

VAE latent 与视野 · DiT 的先验/后验/引力场 · 条件作为一块"透镜"
一句话:VAE 把像素压成 8×8×48 的 latent(平滑、冗余、通道尺度不均);DiT 在 latent 上学一个"多引力加权合成"的速度场, 把各向同性的 N(0,I) 搬运成高度各向异性的数据分布;而条件只改先验 —— 等于给这些引力加一块按条件调音量的透镜。

第一幕VAE:像素 ↔ 8×8×48 的 latent

先看形状,再看"视野"和"冗余",最后看"通道尺度不均" —— 这三点决定了后面 DiT 面对的是什么样的分布。

1.1 形状流水线

128×128 图像
  → patchify 2×2        → 64×64×12
  → 编码器(3 次下采样)  → 8×8
  → 96 通道 = 48 mean + 48 logvar
  → z = μ + σ·ε         → latent 8×8×48
  → 解码器(3 次上采样)  → 64×64×3
  → unpatchify 2×2      → 128×128
组件数量
WanCausalConv3d62(编码 26 + 解码 34)
WanAttentionBlock2(编/解码各 1 个 mid-block)
普通 Conv2d10

双相机时,两个相机的 latent 在宽度方向拼接:128×128×2 → latent 8×16。

1.2 "8×8×48" 该怎么读

不是"一个 48 维高斯",而是:每个空间位置各有一个 48 维对角高斯(每位置自己的 μ 和 σ);一帧有 8×8 = 64 个这样的高斯。48 个通道之间独立(对角),但尺度差别很大。

1.3 视野:一个 latent 单元能"看到"多少像素

1.71 → 29.16RF σ(px),17 倍
8.6×中心半径 vs r90(中心强、边缘弱)
0.9959相邻 latent 的视野相似度
≈121 帧时间视野(时间下采样 4×)

这三点的含义:latent 空间是平滑的、有冗余的、越深越"全局"的。所以 DiT 面对的不是 24,576 个独立变量,而是一个高度相关的场。

2.1 训练一步到底在算什么

x0      = latent                          # 干净 latent
eps     = torch.zeros_like(x0).normal_()  # ε ~ N(0, I)
sigma   = 逐帧随机                          # 噪声水平
x_sigma = (1-sigma)*x0 + sigma*eps        # 网络的输入
target  = eps - x0 = (x_sigma - x0)/sigma # 网络要输出的东西
loss    = || net(x_sigma, sigma[, c]) - target ||²
配置一个 chunk 的 latentlatent token网络输出行数action token

2.3 为什么"平均"是对的:训练的真实机制

数学上,平方损失的最优解是条件期望;而条件期望按定义就是后验加权平均。实现上更直接:

落在同一个读数附近的训练样本,其 x₀ 的比例恰好等于后验(贝叶斯的直接后果)。 所以对它们的 target 取普通算术平均,就等于后验加权平均。

顺带说明:"同一小段读数"不是代码里的步骤,而是网络平滑性造成的分辨单元。邻域越窄越接近逐点条件期望(0.2 → −0.175;0.01 → −0.1947;→0 → −0.19475)。

第三幕条件:给引力场加一块透镜

这一幕只有一句话:条件不增加源的个数,只改每个源的权重。

3.1 数学上:只换先验

无条件:  p(x₀ | x_σ, σ)     ∝  p_data(x₀)  · N(x_σ; (1−σ)x₀, σ²I)
有条件:  p(x₀ | x_σ, σ, c)  ∝  p(x₀ | c)   · N(x_σ; (1−σ)x₀, σ²I)
                                 └── 只有这一项被换掉(先验)──┘
问题答案
似然变了吗?没变 —— 加噪是在 x₀ 上做的,与 c 无关
源的个数变了吗?没变 —— 改的是每个源的权重;权重被压到 0 时效果上等同"删源"
训练要算先验吗?不要 —— 样本是 (x₀, c) 配对抽出的,"先验"就是"带这个 c 的样本构成"

3.2 代码级:条件从哪进模型

训练时把四段拼成一条序列,用一张掩码规定谁能看谁:

hidden_states = torch.cat([noisy_latent,            # ← 参与损失
                           clean_latent,            # ← 条件
                           noisy_action,            # ← 参与损失
                           clean_action], dim=1)    # ← 条件
latent_hs, _, action_hs, _, _ = torch.split(...)    # 条件段输出被丢弃
查询 → 键允许?规则
条件 → 条件✅仅因果
加噪 → 条件✅因果,但排除自己所在的帧块 ← 条件就是从这里进入 target 的
加噪 → 加噪✅仅同一帧块内
条件 → 加噪❌禁止

加噪只加在 target 上:条件帧默认干净,但有 50% 概率被额外加噪(noisy_cond_prob=0.5,噪声水平取高区间 0.5~1.0;action 分支为 0.0)—— 训练模型容忍"脏观测",因为自回归 rollout 时条件帧正是模型自己上一步的输出。

推理时改为:观测帧先跑一次把 K/V 存进 attn_caches,之后每步只送 noisy latent;文本仍走 cross-attention。 "无条件"= 换掉条件,不是另一个模型:noise_pred = uncond + guidance_scale * (cond - uncond)。

3.3 透镜的三条性质

#性质含义
①乘性权重 = 先验 × 似然,条件乘在先验上 → 不能凭空造源(数据里没有的,条件也照不亮)
②按样本/类别调不是按位置连续调;更像"一排音量旋钮",每个 c 一张设定表
③连 σ=1 的靶心一起改E[x₀] → E[x₀|c],从第一步就偏置,不只是后期

拔河:若条件指向 −1(先验 0.9/0.1)而读数偏向 +1(似然 0.579/0.388),则后验 = 0.858 / 0.142 → 条件赢。 条件足够强时能压过读数的倾向 —— 这就是"可控"的来源。

4.2 耦合的部分:注意力掩码(实测)

掩码把帧号量化时,视频用偶数 2c、动作用奇数 2c+1 —— 这个 ±1 的错位就是耦合的开关:

frame_ids = cat([latent_frame_id // chunk_size * 2] * 2
              + [action_frame_id // chunk_size * 2 + 1] * 2)
查询 → 键结果含义
noisy 动作(chunk c)→ clean 视频(chunk c)✅ 允许动作依赖当前视频
noisy 动作 → clean 视频(未来 chunk)❌ 禁止不能看未来
noisy 视频(chunk c+1)→ clean 动作(chunk c)✅ 允许视频能看过去的动作
noisy 视频(chunk c)→ clean 动作(chunk c)❌ 禁止视频看不到同 chunk 的动作
noisy 视频 ↔ noisy 动作(任何 chunk)❌ 双向禁止加噪的跨模态之间不通信:动作只能看干净视频

4.3 为什么这么设计

理由体现
两个模态的"信噪比难度"不同两个 scheduler 的 shift 完全不同(动作可以极端到 0.05)
动作要执行,精度要求高动作步数更多(50 vs 20)
分层决策:先"想清楚世界",再"照着做"视频先跑完并把 K/V 写进 cache,动作再读
动作是确定性执行action_guidance_scale = 1,不对动作做 CFG

代价(结构固有的):① 动作无法反过来影响视频(不能"为了做某个动作而去想象画面"); ② 同一 chunk 内视频看不到动作 → 它不是"动作条件化的视频预测",而更接近 视频 → 动作的逆动力学式结构; ③ 动作质量受限于视频预测质量;④ 两条链各自独立随机采样,同一段视频只对应一份动作采样。

在"世界模型"谱系里的位置:世界模型(视频)+ 逆动力学头(动作)的单向串联,而不是联合扩散 —— 联合扩散会让两个模态在每一步互相看对方的加噪状态,这里明确禁止了。

4.4 收口:把两条链放回"引力场"的语言里

前面几节都是工程细节。这一节把整个模型压回第二幕那套语言 —— 它不是"两个独立的扩散模型",而是同一个联合分布按"视频先行"这一种因果分解切出来的两片,每一片各自有一个引力场。

引力场的概念(第二幕)在这个模型里的具体对应
源(每个样本一个点源)数据集里的一个 视频 chunk(视频场)/ 一个 动作 chunk(动作场)
在 48×4×8×16 / 30×4×4×1 维空间里的一个点
引力场(源按先验叠加出的密度场)视频场:p(v | h);动作场:p(a | h, v̂)
各自的引力场只由自己那个条件分布决定
透镜(换先验 = 重新加权源)历史 h(cache)、以及动作场独有的 v̂、文本 prompt
乘性、不造源、能把源压到 0(等于删除)
读数 x_σ当前正在去噪的那个 latent;每一帧有自己的 σ
合成方向 / 速度 v每一步网络输出 v = (x_σ − E[x₀|x_σ,σ,cond])/σ
视频链走 self.scheduler,动作链走 action_scheduler

两条链的"透镜"性质不一样

透镜由什么决定性质
视频场真实观测视频 + 过去已执行的动作确定的(给定历史就是确定的)
动作场上面这些 + 本轮预测出来的视频 v̂随机的 —— v̂ 是视频场的一次采样

所以动作链实际在采的是把视频采样积掉之后的边缘分布:

p(a_t | h)  =  ∫ p(a_t | h, v_t) · p(v_t | h) dv_t
                                    ↑ 推理时用"自己生成的那一个 v̂"代替这次积分

这个框架推出来的两个结论

结论为什么
A. 模型答不了"what-if"
"如果我做这个动作,画面会变成什么?"		回答它需要 p(v_t | h, a_t),也就是需要 noisy 视频 → 同 chunk 的 clean 动作 这条边;而掩码里 2c+1 < 2c 不成立。
这是"视频先跑、动作后跑"这个顺序的必然代价,不是训练技巧问题 —— 要打开它得改掩码。
B. "两个独立引力场"只是目标层面的理想化目标上:两个场分别由各自的条件分布决定 ✅。
实现上:两条链共用同一个 30 层骨干,两个 loss 的梯度在共享参数里相加(多任务学习)。
所以信息流是单向的,梯度是双向的。

一句话收口:
两条链 = 同一个联合分布的两个条件切片,各自是一个引力场;
历史(以及动作场独有的 v̂)是作用在场上的多变的透镜;
每一步去噪 = 在那个 σ 特有的场里,取当前读数处的加权合成方向;
而"谁先谁后"这个因果选择,就写在 frame_id 那个 ±1 的错位里。

附录 AFlow-GRPO:从 flow 的 v 到可优化的随机策略

前面五幕讲的是本项目和六个世界-动作模型。这个附录讲**另一条线**:如何把 flow 模型本身变成一个可以做强化学习的随机策略 —— [Flow-GRPO](https://arxiv.org/abs/2505.05470)(代码 flow_grpo)。
选它的原因是:它把前面所有概念(引力场 / score / 透镜 / 密度记账)一次性用上了 —— 而且每一步都能用代码和数值验证。 本附录里所有数字都是在 1 维或解析可算的 toy 上真跑出来的,不是手画。

一句话:把 flow 的确定性 ODE 换成一个边缘分布完全相同的随机 SDE ⇒ 每一步都有简单可算的高斯似然 ⇒ 才能用组内相对奖励算策略梯度 ⇒ 把那些"很难写成损失、但很容易打分"的目标学进来。

A.1 要解决的问题:为什么必须换采样器

ODE 采样(flow 原生)为什么不能直接做 RL
给定初始噪声 ε轨迹唯一策略退化成 δ 分布,没有"似然"可言
每步似然δ 函数(无法使用)构造不出重要性比 ρ
探索来源只有初始噪声一个论文 §5.3 实测:随机性↓ → 奖励提升明显变慢

A.2 Step 1:插值 → 条件平均速度 v

约定:σ=0 干净数据,σ=1 纯噪声;生成方向是 σ 递减。插值定义为

x_σ = (1−σ)·x₀ + σ·ε ,   x₀ ~ p_data ,   ε ~ N(0,I)

对 σ 求导得 dx_σ/dσ = ε − x₀(逐样本成立);取条件期望就是流匹配的训练目标:

v*(x,σ) = E[ ε − x₀ | x_σ = x ] = ( x − E[x₀ | x_σ = x] ) / σ

A.3 Step 2:两个恒等式(后面全靠它们)

对 p_σ(x) = ∫ p_data(x₀)·N(x; (1−σ)x₀, σ²) dx₀ 求梯度,认出两个积分(全概率与贝叶斯),就得到:

(a)  Tweedie:      E[x₀ | x_σ] = ( x + σ²·∇log p_σ ) / (1−σ)
(b)  score ↔ v:    ∇log p_σ(x) = − ( x + (1−σ)·v(x,σ) ) / σ      ← 最关键的一行

A.4 Step 3:给 ODE 采样器发"合格证"

训练只保证"每个点上 v 准"(局部),采样需要"整体分布对"(全局)—— 这两件事不等价,必须证:

命题:若 v = v*,且 x 按 dx = v* dσ 从 σ=1 走到 σ=0,
     则每个 σ 时刻 x 的分布都等于 p_σ ⟹ σ=0 时等于 p_data。

证法:取任意测试函数 h
  插值族: d/dσ E[h(x_σ)] = E[∇h·(ε−x₀)] = E[∇h·E[ε−x₀|x_σ]] = E[∇h·v*]     ← 塔性质
  ODE 族: d/dσ E[h(y_σ)] = E[∇h·v*]
  对所有 h 相同 + 起点相同 ⟹ 分布处处相同 ✓

A.5 Step 4–5:一族等价 SDE

把 ODE 换成一般 SDE dx = f dσ + g dW,用同一张考卷(测试函数)解出漂移必须是什么:

d E[h] = E[∇h·f] dσ + (g²/2)·E[Δh] dσ ,   E[Δh] = −E[∇h·∇log p]
令其等于 Step 3 的 E[∇h·v*] dσ  ⟹
        f = v* + (g²/2)·∇log p_σ          … σ 递增方向(加噪)
换到生成方向(σ 递减,负号来自反向时间):
        f = v* − (g²/2)·∇log p_σ          … 代码里真正用的

结构:g 是我们自由选的,f 被 g 唯一决定;`g=0` 就退回 ODE。

A.6 补偿机制:一步的账 + 密度层面的相消

常见误解:"在 v 上加一个密度方向的偏移,结果不就偏了吗?"
答:那一项不是随手加的偏移,而是噪声的精确补偿量 —— 而且补偿发生在同一步里,不是"先走偏再修回来"。 少补或多补,分布确实会坏(见下表)。

A.7 从"粒子"到"密度":通量与收支

很多人卡在这里:前面一直在讲"一个粒子怎么走",密度方程从哪来?答案:**中间只隔着一个"通量 = 密度 × 速度"**。

离散(数格子):  Δp_i = − (F_i − F_{i−1})/Δx · Δσ        "这个格子 = 左边流进 − 右边流出"
连续(取极限):  ∂_σ p = − ∂_x F ,   F = f·p = 密度 × 速度
噪声也是通量:  F_diff = −(g²/2)·∂_x p    ⇒  ∂_σ p = −∂_x(f p) + (g²/2) p''

A.9 每个参数为什么没被漂移/噪声淹没

代码里每一步的均值是:

mean = x·(1 + g²dσ/(2σ))  +  v_θ·dσ·(1 + g²(1−σ)/(2σ))

代入 g² = σ/(1−σ)·nl² 化简(符号化推导):

v_θ 的系数 B = dσ·(1 + nl²/2)      ← 与 σ 【无关】的常数!
x 的系数   A = 1 + dσ·nl²/(2(1−σ))  ← 依赖 σ,但不含 θ

A.10 离散化:每步的 log-prob 从哪来

走一步:  x' = mean_θ(x) + s·ξ ,   ξ~N(0,1) ,   s = std_dev_t·√(−dσ)     ← s 与 θ 无关
对数密度: log π_θ(x'|x) = −(x'−mean_θ)²/(2s²) − log s − ½log(2π)
                       = −ξ²/2 − log s − ½log(2π)

代码里的两个细节:
  · prev_sample 上 .detach()  ⇒ θ 只能通过【均值】影响 log-prob
  · 对非 batch 维取 .mean() 而不是 .sum()  ⇒ 否则 log-prob 大几千倍,ρ 会爆

一个具体数:s=0.05, ξ=1.5 → log π = −1.125 + 2.996 − 0.919 = +0.952。 若 θ 把均值挪 0.005(0.1 个 s),同一点的 log-prob 变成 +1.097 ⇒ ρ=1.16, 远超 clip=1e-3 —— 这就是那个极小裁剪范围的原因。

A.11 GRPO:优势、重要性比、loss

① 采样(no_grad)   同一 prompt 采 G 个,记下【每一步】的 log π_old
② 打分            每个样本一个标量奖励 R_i
③ 优势(组内标准化) A_i = (R_i − R̄_group)/(std_group + 1e−4)      ← 不需要 value 网络
④ 广播到各步+裁剪  A_i 复制到 T 步;clamp(A_i, ±5)
⑤ 每步重要性比     ρ_j = exp( log π_θ(x_j) − log π_old(x_j) )
⑥ 裁剪 surrogate   L = mean( max(−Aρ, −A·clip(ρ, 1±1e−3)) ) + β·KL
⑦ KL(闭式高斯)     ‖m_θ − m_ref‖²/(2s²),参考策略 = 关掉 LoRA(disable_adapter)
超参(通用配置)值说明
组大小 G4(或 24)GRPO 的"组"
训练步 T⌊20 × 0.99⌋ = 19timestep_fraction=0.99,最后一步不训
clip_range1e-3极小 ⇒ 每步只许动 0.1%
adv_clip_max±5截断极端优势
KL 权重 β0.004防 reward hacking
num_inner_epochs1见下面那个"容易漏掉的点"
一个容易漏掉的点:梯度累积覆盖整条去噪链(gas = 1×T),且 inner_epochs=1 ⇒ 同一个子批次内部 θ 不动 ⇒ 该批次里 ρ ≡ 1、裁剪不起作用 ⇒ 更新退化成普通策略梯度 + 组内基线。只有同一批数据被用 ≥2 次时,ρ≠1、裁剪才真正生效。

A.12 噪声与"运气":谁在处理什么

两个"抵消"别混
层次 A(采样器/密度):噪声的扩散 +(g²/2)p'' ⇄ 漂移的补偿 −(g²/2)p'' ⇒ 精确抵消,分布不变。
层次 B(奖励/优势):运气 η 不抵消,只被分解 —— 批平均被减掉,个体偏离原样留下(那是估计方差)。

A.13 为什么奖励会"落在每一步"上

先纠正一个前提:奖励只有终点一个。代码里 R_i 只在最终样本上计算(检测器 / OCR / 偏好模型), 没有任何 per-step 奖励。每步之所以出现,是因为优势被 .repeat(1, T) 广播 —— 每步是分摊同一个 A。

轨迹的概率 = 各步条件概率的【乘积】  π_θ(traj) = Π_j π_θ(x_{j+1} | x_j)
取对数     → 变成【求和】            log π_θ = Σ_j log π_θ(x_{j+1} | x_j)
求导                                ∇log π_θ(traj) = Σ_j ∇log π_θ(x_{j+1} | x_j)

⇒ ∇L = − A · Σ_j ∇log π_j = − A · ∇log π_θ(整条轨迹)

所以不是"我们选择奖励每步",而是"轨迹概率的对数天然是各步之和" —— 求和来自概率的乘积结构。 另一个角度:θ 只能通过每一步的均值起作用(v_θ(x_j,σ_j)), 所以"改变终点分布"只能通过改变各步的条件分布来实现,没有"直接改终点概率"这个操作。

"只看终点的比值"和"每步比值"在数学上是同一件事:ρ_traj = Π_j ρ_j = exp(Σ_j Δlog π_j)。 但代码用每步的 ρ,原因是信赖域的粒度:

做法(ε=1e-3, T=19)效果
逐步裁剪(每步 ρ_j ∈ [1±1e-3])整条轨迹上界 1.001¹⁹ = 1.0192 ⇒ 轨迹级自由度 1.9% ✅
只裁剪轨迹级比值到 1±1e-3每步只许动 1.001^(1/19) = 1.0000526 ⇒ 0.0053%(比前者紧 94.7%,几乎学不动)

而真正"给每步单独定分"(per-step credit assignment)需要中间奖励或 value 网络 —— 生成任务里两者都没有(半噪声的图没法打分);这正是 GRPO 想省掉的东西,代价就是没有逐步信用分配。

A.14 奖励"路径"还是奖励"通向目的的速度"?

这个问题正好踩在方法论的分岔口上。论文自己列了 T2I 对齐的五条主线:

(1) direct fine-tuning with scalar rewards [30–33]    ← "直接奖励速度"属于这里
(2) Reward Weighted Regression (RWR)
(3) DPO 及其变体
(4) PPO-style policy gradients                        ← Flow-GRPO 在这里
(5) training-free alignment

路线 A(可微奖励反传,DRaFT / ReFL / AlignProp):如果奖励可微,可以完全不做路径抽样,把终点奖励直接对场求导:

输出:x(T) = F_θ(ε)          ← 整条采样链留在计算图里
梯度:∂R/∂θ = (∂R/∂x(T)) · (∂x(T)/∂θ)

三个直接推论:不需要似然(所以不必把 ODE 变成 SDE)、梯度无噪声(精确)、但奖励必须可微 + 显存昂贵。

A. 反传奖励(DRaFT/ReFL/AlignProp)B. GRPO(本方法)
奖励要求必须可微只要标量(黑盒打分器都行)
需要似然不需要必须要(所以必须 ODE→SDE)
显存整条链(贵)只看 log-prob(便宜)
梯度无噪声(精确)有噪声(无偏,靠平均)
主要风险奖励被钻空子(对抗性、过拟合奖励)方差大、无逐步信用分配
典型奖励CLIP 分数、检测框回归、可微渲染/物理OCR / 规则校验 / 偏好模型
为什么"不可微奖励"时只能走路径:一个标量"好/坏"不提供方向 —— 你不知道该往哪改场。要拿到方向只有两条路: 奖励本身可微(路线 A),或用"这次随机方向 ξ 是否与好结果相关"统计地估出方向 (E[A·ξ] = s·∂E[R]/∂m,路线 B)。后者需要知道"这次走的是哪个方向",也就是每步的似然 —— 这就是前面那整套推导存在的理由。

三个折中:① 可微奖励当辅助项 L = L_GRPO + λ(−R_diff),只对最后几步保留计算图; ② 先 reflow/蒸馏修直路径(步数变少 ⇒ 反传代价低,路径也更接近直线); ③ 引入 per-step 优势(代码里那个广播就是为它留的口子)。

A.15 步骤会不会变多?(这是真实风险,而且论文没测)

分布被 RL 倾斜之后,场的形状会变 ⇒ 同样的精度可能需要更多采样步。在 1 维两原子 toy 上实测 (20000 条样本,比较端点标准差与解析值的误差):

精度要求训练前(0.5/0.5)RL 之后(0.8/0.2)倍数
1% 误差8 步32 步4×
0.4% 误差8 步128 步16×

机制:倾斜 ⇒ 场的"切换区"(两个候选的后验权重快速倒向一边的地方)变陡 ⇒ 粗步长一步跨过就积分错。

★ 最强的保护:奖励是在【训练步数】上测出来的。
若 RL 让场需要更多步才采得好,训练时的采样本身就变差 ⇒ 奖励掉 ⇒ 更新被惩罚回来。 所以工程做法是:把训练步数设成你要部署的步数。 论文的配置是训练 20 / 评估 50(它关心 40 步出好图,不关心少步部署);若要 4 步部署,就该让 sample.num_steps = 4,让 reward 在你关心的那个步数上被测量。

另外两条保护:KL(β=0.004)+ LoRA 把 θ 拉在原模型附近、只做低秩小扰动(上面 toy 用的是"倾斜到极限",没有这个约束); 以及奖励通常与画质弱相关(偏好模型对模糊、伪影敏感)。

怎么验证(可执行):① 画「质量 vs 采样步数」曲线,训练前后对比;② 测轨迹弯曲度(弧长/弦长、相邻步方向夹角); ③ 注意论文只报了固定 40 步下质量没明显掉,没报少步对比 ⇒ 这是空白,不能当成"已验证没问题"。

三个补救:① 训练时就少步采样;② 加强 KL(β↑)或早停;③ RL 之后做一次 reflow/蒸馏修直路径 (标准做法:先对齐奖励,再蒸馏到少步)。

一个反例(说明不是必然变差):前面 toy 里 RL 之后弯曲度是 1.99 → 1.59(更直了) —— 因为奖励把分布推向更集中的区域,而单点场的路径恰好是直线。方向取决于奖励偏好什么,但"会不会需要更多步"必须测过才算。

A.17 诚实边界清单

#边界
1等价 SDE 是连续时间结论;离散化有偏差(实测 ~1%),所以 Denoising Reduction 是近似,不是定理。

3KL 是闭式高斯且对空间维取平均(不是真 KL 的求和),是经过缩放的版本。
4两原子 toy 对补偿系数不敏感(强吸引子钉住终点),要连续分布才看得出 c 必须等于 1。
5advantage 沿时间步广播 ⇒ 没有 per-step 信用分配(代码注释也这么说)。
6论文只在 T2I 验证,视频/机器人明确列为 future work。
7RL 不破坏"模型族/接口/ODE 采样能力",但会影响"少步采样质量"(见 A.15 的 toy 实测:1% 误差需 8→32 步)—— 论文未测,是空白。
8baseline 用含自身的组均值 ⇒ O(1/G) 小偏差(严格无偏是留一均值 R̄_{−i})。
9本附录所有数值来自 1 维/解析可算的 toy(可复现,脚本在 tools/vae_dit_story/),不是真实图像模型的实测。

A.18 一页速查

【链条】
  插值 x_σ=(1−σ)x₀+σε  →  v*=E[ε−x₀|x_σ]=(x−E[x₀|x])/σ
  →  Tweedie 与 score 两个恒等式        →  ODE 采样器合格(局部⟹全局)
  →  一族等价 SDE: f = v* ∓ (g²/2)∇log p   (g 自由,漂移被唯一决定)
  →  通量守恒: 总通量 = v*p,与 ODE 完全相同 ⇒ 分布不变
  →  每步是简单高斯 ⇒ 每步 log-prob 可算
  →  GRPO: 组内标准化出优势(无 value)→ 逐步 ρ → 裁剪 surrogate + 闭式 KL
  →  梯度落回 θ: ∇L = −A·Σ_j (ξ_j/s_j)·∂m_j/∂θ

【三个"不"】
  · 噪声不需要被抵消 —— 它是探索方向;E[A·ξ]=s·∂E[R]/∂m(期望是梯度)
  · 抖动幅度与 θ 无关(s 只依赖 σ、noise_level)⇒ RL 只挪中心,不让轨迹变歪
  · 补偿不改变"目的地分布"—— 它只在【群体/密度】层面精确相消

【两个"抵消"别混】
  层次 A(采样器/密度): 扩散 +(g²/2)p''  ⇄  补偿 −(g²/2)p''   ⇒ 精确抵消
  层次 B(奖励/优势):   运气 η                                    ⇒ 不抵消,只被分解(批平均去掉,个体留下)

【一句话】
  把 flow 的确定性 ODE 换成边缘分布相同的随机 SDE ⇒ 每步有可算似然
  ⇒ 才能用组内相对奖励做策略梯度 ⇒ 把"难写成损失但容易打分"的目标学进来。
